# 运行前更新

版本号保存在`VERSION`，当前为2.0.0。更新源固定为[GitHub上的Roylyl/DeerPhotos](https://github.com/Roylyl/DeerPhotos)，以`main`分支当前提交中的版本和文件为准，不依赖Release附件。

## 执行方式

在技能根目录运行：

```sh
python3 scripts/ensure_latest.py
```

脚本默认定位自身所在的技能目录，与终端当前路径无关。维护者需要指定另一个技能副本时可使用`--skill-dir`参数。没有离线放行或跳过更新的参数。

每次请求都访问GitHub，读取最新提交及对应`VERSION`。提交标识用于选择同一份远端快照，不计算本地文件哈希。若上次安装记录与本次远端一致，仅检查运行所需的入口和引用文件是否存在，不重复下载整包。

| 结果 | 行为 |
| --- | --- |
| 退出码0且`status`为`ready` | 本次可以继续；`updated`表示是否刚完成更新 |
| `updated`为`true` | 重新读取更新后的`SKILL.md`和任务所需档案 |
| 退出码20且`status`为`blocked` | 显示`reason`并停止生图 |
| 其他错误或没有有效结果 | 停止，不把没有输出当成成功 |

不要将本次检查结果用于下一条生图或编辑请求。技能由Agent执行，检查脚本不是独立的生图服务；Agent必须先完成此步骤，才调用生图工具。

## 安装副本

更新包固定到刚查得的Git提交，先下载到技能旁边的临时目录，再解包并检查必要入口和引用资源。完成后将旧技能目录移动到同级隐藏备份目录，例如`deerphotos`对应`.deerphotos-backups/`，然后放入新版本。替换失败会尝试恢复旧目录，当前任务始终停止。

成功更新时，JSON中的`backup`提供旧副本位置。旧副本包含之前的人物自定义记录与其他文件；新版本不自动合并这些内容。生成照片建议保存到技能目录以外，避免与更新文件混放。

`.deerphotos-update.json`仅记录上次安装的提交与版本，不能作为离线放行依据，也不应手动修改。更新锁位于技能目录旁，例如`.deerphotos-update.lock`；若进程被强制终止，应先确认没有更新进程，再删除遗留锁并重新执行检查。

## Git开发目录

脚本识别根目录中的`.git`。存在未提交改动时停止；干净工作树仅允许快进到GitHub的最新提交，不创建提交、不执行推送。分叉、本地领先远端或检查过程中远端变化时也停止。

版本号相同但远端提交变化，仍需更新文件。本地版本高于远端或GitHub尚无`VERSION`时，不降级，也不允许生图。只有将相应版本发布到GitHub后，才能通过检查；写入本地版本号不等于已经发布。
