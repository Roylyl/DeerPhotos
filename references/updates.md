# 运行前更新

由Agent在每次生图或改图请求开始时访问[GitHub官网项目](https://github.com/Roylyl/DeerPhotos)，比较本地安装与`main`最新源码，有更新时尝试安装；检查或更新失败则继续使用本地可用版本生成。更新不依赖特定操作系统、Python命令或固定脚本返回值。

## 查询与比较

1. 打开[main分支](https://github.com/Roylyl/DeerPhotos/tree/main)，取得最新提交的完整标识。
2. 读取该提交下的`VERSION`，使用官网文件页或官方Raw地址。文件地址为`https://raw.githubusercontent.com/Roylyl/DeerPhotos/<commit>/VERSION`，将`<commit>`替换为刚查得的真实提交标识。
3. 读取本地`VERSION`和`.deerphotos-update.json`。安装记录中的`repository`应为`Roylyl/DeerPhotos`，`version`和`commit`应与本次远端查询相符，本地版本也必须一致。
4. 比较版本号的三个数字部分。本地低于远端、提交不同或没有可靠安装记录时，下载安装最新源码。相同版本也可能有源码更新；不能只比较版本号。已匹配的安装仍应确认技能入口、人物档案及引用图片存在，缺失时重新安装。

每次都要联网查询，安装记录不能代替官网检查。官网页面暂时无法读取时，可使用GitHub官方API的`repos/Roylyl/DeerPhotos/commits/main`取得提交，再读取固定提交的版本文件。无法取得可靠信息时结束本次更新尝试，继续使用本地版本，不能猜测远端版本。远端缺少版本文件、版本格式异常或本地版本高于远端时，说明实际情况，不自动降级。

## 下载与安装

从`https://github.com/Roylyl/DeerPhotos/archive/<commit>.zip`下载刚查得提交的完整源码，也可使用官方`https://codeload.github.com/Roylyl/DeerPhotos/zip/<commit>`地址。不要下载检查后可能变化的分支压缩包，不使用第三方镜像。提交标识用于指定源码，不要求计算文件哈希。

Agent按当前系统选择可用工具。Windows可使用PowerShell的`Invoke-WebRequest`和`Expand-Archive`；macOS可使用`curl -fL`和`unzip`，也可使用环境提供的下载与文件工具。路径包含空格或中文时正确引用，不照搬其他系统的路径、shell语法或`python3`命令。工具出错时保留并读取标准错误；根据具体错误更换可用工具，不盲目重复。

安装顺序：

1. 在技能目录旁边创建临时目录，下载并解压源码。拒绝指向解压目录之外的路径或不安全链接。
2. 找到解压包中直接包含`SKILL.md`的根目录。核对`VERSION`与本次查询一致，技能名称为`deerphotos`，存在`agents/openai.yaml`、`references/characters.json`以及人物档案引用的图片。不需要额外计算哈希。
3. 将终端工作目录切换到技能目录以外，并关闭本次操作持有的目录或文件句柄，避免Windows因当前工作目录被占用而无法替换。另一个进程仍占用文件时，说明具体路径，不强制终止无关进程。
4. 将旧安装移动到同级隐藏备份目录，例如`.DeerPhotos-backups/<唯一名称>/`，然后把已检查的新源码目录放到原安装位置。若替换失败，恢复旧目录并使用旧版继续生成；恢复也失败时保留备份和临时文件，优先从可用备份读取规则、档案和参考图继续生成，并告知实际位置；不能混用不完整的新目录。
5. 安装成功后，在新目录写入`.deerphotos-update.json`，记录`repository`、`branch`、实际`commit`、`version`和检查时间`checked_at`。不能提前写入成功记录，也不能根据旧缓存伪造记录。
6. 重新读取新安装的`SKILL.md`，随后读取任务需要的人物档案和参考图，再生图。

旧目录保留用户自定义内容，新版本不自动合并。生成照片应存到技能安装目录以外。并发更新时不同时替换同一目录；使用完整可用的本地副本或备份继续生成；遗留锁必须确认无更新进程后才处理。

## Git开发目录

如果目标是Git工作树，先查看工作树状态。有未提交改动时跳过自动更新，使用现有版本继续生成，不覆盖开发内容。干净工作树可从官方仓库获取刚检查的提交并仅做快进更新；不能重置、强行覆盖、创建提交或推送。本地分叉、领先远端或无法确认更新结果时保留本地版本并继续生成。不要用源码包替换开发目录的`.git`。

## 失败处理

检查或更新失败不阻止生图。不反复重试、不要求用户先排查环境，保留或恢复本地可用副本，继续完成当前生成或编辑请求。Python不可用、网络错误、下载失败、权限不足、文件占用，以及旧脚本的非零退出码或`blocked`输出，都只表示本次更新没有完成。

交付结果时附上一句：“本次更新未完成，已使用本地版本生成。请前往[GitHub项目](https://github.com/Roylyl/DeerPhotos)下载并更新最新版Skill。”如果实际没有生成成功，不得使用“已生成”的表述；按实际结果说明，并保留更新链接。

不伪造版本检查或安装记录。仅当本地及备份中的必要参考资源均不可用，或生图工具本身不可用时，说明实际缺失项。更新成功不依赖`status: ready`字符串。仓库中的`ensure_latest.py`仅作为旧版辅助工具保留，不是当前Skill的必经入口，其旧版停止要求不覆盖本节规则。
